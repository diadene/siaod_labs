## Тема

**Простые алгоритмы сортировки и рандомизированный QuickSort**

## Цель работы

Изучить и реализовать простые алгоритмы сортировки (Bubble Sort, Insertion Sort, Selection Sort), а также рандомизированный алгоритм быстрой сортировки (QuickSort). Сравнить алгоритмы по количеству сравнений, перемещений элементов и времени выполнения на различных типах входных данных. Проверить стабильность сортировок и корректность реализаций.

## 1. Реализованные алгоритмы

В работе реализованы четыре алгоритма.

### 1.1. Сортировка пузырьком (Bubble Sort)

Алгоритм последовательно сравнивает соседние элементы и меняет их местами, если они расположены в неправильном порядке. После каждого прохода наибольший из оставшихся элементов оказывается в конце рассматриваемой части массива.

В реализации используется флаг `swapped`: если за проход не было ни одного обмена, массив уже отсортирован и алгоритм завершает работу досрочно.

- Лучший случай: **O(n)** — входной массив уже упорядочен.
- Средний случай: **O(n²)**.
- Худший случай: **O(n²)** — массив упорядочен в обратном порядке.
- Дополнительная память: **O(1)** для самого алгоритма сортировки (не учитывая копирование массива в реализации).
- Стабильность: **стабильный** алгоритм.

### 1.2. Сортировка вставками (Insertion Sort)

Алгоритм рассматривает элементы по одному. Каждый очередной элемент вставляется в правильную позицию среди уже обработанной, отсортированной части массива. Для освобождения места элементы, большие вставляемого, сдвигаются вправо.

- Лучший случай: **O(n)** — массив уже упорядочен.
- Средний случай: **O(n²)**.
- Худший случай: **O(n²)** — обратный порядок.
- Дополнительная память: **O(1)** для сортировки (не учитывая копирование массива).
- Стабильность: **стабильный** алгоритм.

### 1.3. Сортировка выбором (Selection Sort)

На каждой итерации алгоритм находит минимальный элемент неотсортированной части массива и помещает его в начало этой части. Таким образом, отсортированная область постепенно увеличивается.

- Лучший, средний и худший случаи: **O(n²)**.
- Количество сравнений не зависит от исходного порядка элементов и равно `n(n − 1) / 2`.
- Количество обменов не превышает `n − 1`.
- Дополнительная память: **O(1)** для сортировки (не учитывая копирование массива).
- Стабильность: **нестабильный** алгоритм в данной реализации.

### 1.4. Рандомизированная быстрая сортировка (QuickSort)

Для каждого подмассива случайным образом выбирается опорный элемент (pivot). Остальные элементы распределяются на три группы: меньше опорного, равные ему и больше него. Затем рекурсивно сортируются группы меньших и больших элементов.

Использование трёх групп позволяет корректно и эффективно обрабатывать повторяющиеся значения. Для подмассивов длиной 0 или 1 рекурсия завершается.

- Ожидаемая временная сложность: **O(n log n)**.
- Худший случай: **O(n²)**.
- Дополнительная память: в данной реализации используются дополнительные списки и рекурсивные вызовы, поэтому она не является реализацией QuickSort с разделением массива на месте.
- Стабильность: **стабильный** в данной конкретной реализации, поскольку элементы добавляются в группы в исходном порядке.

Следует учитывать, что стабильность и использование дополнительной памяти здесь обусловлены выбранной реализацией QuickSort, а не являются обязательными свойствами всех вариантов этого алгоритма.

## 2. Методика эксперимента

Для сравнения алгоритмов были подготовлены три класса входных данных:

1. **Упорядоченный массив** — элементы расположены по возрастанию.
2. **Случайный массив** — элементы расположены в случайном порядке.
3. **Обратно упорядоченный массив** — элементы расположены по убыванию.

Для простых сортировок использовались размеры:

`500, 1000, 2000, 4000, 8000`.

Для QuickSort использовались размеры:

`1000, 3000, 10000, 30000, 100000`.

Перед измерениями выполнялся прогрев. Для каждого набора параметров проводилось не менее пяти повторов, а итоговым временем считалась медиана результатов. Это позволяет уменьшить влияние случайных колебаний времени выполнения.

Измерения проводились на одном компьютере в одной программной среде. Поэтому абсолютные значения времени характеризуют конкретный запуск и оборудование, а для анализа сложности важнее тенденции изменения времени при увеличении размера массива.

### 2.1. Подсчёт операций

Для Bubble Sort и Insertion Sort учитывались сравнения ключей и обмены/перемещения элементов. Для Selection Sort учитывались сравнения элементов и фактические обмены.

В Insertion Sort счётчик сравнений учитывает только сравнения значений массива с вставляемым элементом. Проверка границы `j >= 0` в него не входит. Счётчик перемещений увеличивается при каждом сдвиге элемента вправо; финальная запись вставляемого элемента отдельно не учитывается.

В Bubble Sort перемещением считается обмен соседних элементов. В Selection Sort перемещением считается обмен найденного минимума с текущим элементом; если элемент уже находится на нужной позиции, обмен не выполняется.

## 3. Проверка корректности и стабильности

Выполнена автоматическая проверка `self_check`. Результат:

Это означает, что реализованные проверки корректности завершились успешно. В частности, проверялись граничные случаи и совпадение результатов сортировки с ожидаемым результатом на тестовых массивах.

Для демонстрации стабильности использовался массив пар, в которых первый элемент — ключ сортировки, а второй — метка исходного элемента:

`[(2, 'a'), (1, 'b'), (2, 'c'), (1, 'd')]`.

Результаты:

| Алгоритм | Результат | Стабильность |
|---|---|---|
| Bubble Sort | `[(1, 'b'), (1, 'd'), (2, 'a'), (2, 'c')]` | Стабильная |
| Insertion Sort | `[(1, 'b'), (1, 'd'), (2, 'a'), (2, 'c')]` | Стабильная |
| Selection Sort | `[(1, 'b'), (1, 'd'), (2, 'c'), (2, 'a')]` | Нестабильная |
| QuickSort | `[(1, 'b'), (1, 'd'), (2, 'a'), (2, 'c')]` | Стабильная |

При стабильной сортировке элементы с одинаковыми ключами сохраняют взаимный исходный порядок. В примере пары с ключом `1` остаются в порядке `b`, `d`, а пары с ключом `2` — в порядке `a`, `c`.

Selection Sort поменял порядок пары `(2, 'a')` и `(2, 'c')`, поэтому данная реализация является нестабильной. QuickSort сохранил порядок равных элементов благодаря распределению элементов по группам с последовательным обходом исходного массива.

### 4.6. Анализ счётчиков

Для упорядоченных массивов Bubble Sort и Insertion Sort выполняют по `n − 1` сравнений и не перемещают элементы. Это подтверждает линейное поведение данных реализаций в лучшем случае.

На случайных массивах Insertion Sort выполняет заметно меньше сравнений, чем Bubble Sort. При этом количество перемещений у двух алгоритмов в приведённых запусках совпадает: в обоих случаях оно соответствует числу инверсий, которые требуется устранить выбранными операциями.

На обратно упорядоченных массивах Bubble Sort и Insertion Sort выполняют почти максимально возможное число сравнений и перемещений, что соответствует квадратичной сложности.

Selection Sort выполняет одинаковое число сравнений для всех типов входа при фиксированном размере массива. Например, для `n = 8000` это `31 996 000` сравнений. Количество обменов при этом значительно меньше, чем у двух других простых алгоритмов: Selection Sort делает не более `n − 1` обменов.

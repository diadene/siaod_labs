## 1. Что сделано

| Компонент           | Реализация                                                                                                  |
|---------------------|-------------------------------------------------------------------------------------------------------------|
| `factorial(n)`      | рекурсивно, базовый случай `n=0 → 1`                                                                        |
| `fib_naive(n)`      | наивная рекурсия `F(n)=F(n−1)+F(n−2)`, счётчик `CALLS["fib_naive"]`                                         |
| `fib_memo(n, memo)` | рекурсия + мемоизация в словаре, счётчик `CALLS["fib_memo"]`                                                |
| `hanoi(n)`          | рекурсивно, возвращает число перемещений                                                                    |
| `DynamicArray`      | буфер фиксированной ёмкости, рост ×2 через `_grow()`                                                        |
| `Stack`             | LIFO поверх `DynamicArray` (`push`/`pop`/`peek`)                                                            |
| `Deque`             | двусвязный список `_Node(value, prev, next)` с `__slots__`; `push_front`/`push_back`/`pop_front`/`pop_back` |

`self_check: OK` — граничные случаи и сверка с эталонами (`math.factorial`, `collections.deque`) проходят.

## 2. Сложности и обоснования

| Операция                                        | Сложность                        | Обоснование                                                                                                                                           |
|-------------------------------------------------|----------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------|
| `factorial(n)`                                  | **O(n)**                         | n умножений; глубина стека O(n). *В docstring заготовки стоит `O = n^2` — это опечатка: величина `n!` растёт быстро, но число операций линейно по n.* |
| `fib_naive(n)`                                  | **O(φⁿ)**, φ≈1.618               | T(n)=T(n−1)+T(n−2)+1; число вызовов ≈ 2·F(n+1)−1 (для n=10 — 177, для n=20 — 21891)                                                                   |
| `fib_memo(n)`                                   | **O(n)**                         | каждый `k` вычисляется один раз и кладётся в `memo`; повторные обращения — O(1)                                                                       |
| `hanoi(n)`                                      | **O(2ⁿ)**                        | T(n)=2T(n−1)+1 ⇒ T(n)=2ⁿ−1 (подтверждено `self_check`)                                                                                                |
| `DynamicArray.append`                           | **амортизированное O(1)**        | метод учёта: начисляем 3 токена на операцию, 1 тратится на запись, 2 копятся на `_grow`; к моменту роста накоплено достаточно                         |
| `Stack.push/pop/peek`                           | амортизированное **O(1)**        | через `DynamicArray`                                                                                                                                  |
| `Deque.push_front/push_back/pop_front/pop_back` | **строго O(1), без амортизации** | фиксированное число присваиваний ссылок; нет буфера, нечего расширять и копировать                                                                    |

**Инвариант пустого дека:** `_head is None ⇔ _tail is None`. В `pop_front`/`pop_back` при опустошении обнуляются **обе**
ручки — иначе вторая остаётся на «мёртвом» узле.

**Порядок присваиваний** в `push_*`/`pop_*` важен: сначала сохраняем ссылку (в новом узле или в переменной), потом
переставляем ручку — иначе старая ссылка теряется до использования.

## 3. Замеры (вариант 4, seed=34)

### 3.1 `DynamicArray.append` — демонстрация амортизированного O (1)

|       n | всего t, c |   t/n, c |
|--------:|-----------:|---------:|
|   1 000 |   0.000102 | 1.02e-07 |
|   3 000 |   0.000330 | 1.10e-07 |
|  10 000 |   0.001208 | 1.21e-07 |
|  30 000 |   0.003466 | 1.16e-07 |
| 100 000 |   0.012948 | 1.30e-07 |

**Вывод:** `t/n` держится в узком диапазоне ~1.0–1.3e-07 с без тренда к росту при увеличении n в 100 раз — это плато,
подтверждающее амортизированное O (1). Колебания — шум измерений и редкие `_grow`. При O (n) на операцию `t/n` росло бы
линейно с n (ср. с `list.insert` ниже).

### 3.2 Вставка в начало: `list.insert(0,x)` vs `collections.deque` vs свой `Deque`

|      n |  list, c | deque, c | custom, c | list/deque | list/custom |
|-------:|---------:|---------:|----------:|-----------:|------------:|
|  1 000 | 0.000122 | 0.000031 |  0.000135 |       3.9× |        0.9× |
|  3 000 | 0.000902 | 0.000085 |  0.000373 |      10.6× |        2.4× |
| 10 000 | 0.009728 | 0.000262 |  0.002049 |      37.1× |        4.7× |
| 30 000 | 0.082059 | 0.000742 |  0.006520 |     110.6× |       12.6× |

**Вывод:**

- `list.insert(0,x)` — **O (n) на операцию** (сдвиг всех элементов); суммарное время растёт ~n². При росте n в 30 раз
  время выросло в ~670 раз — квадратичный тренд.
- `collections.deque.appendleft` — **O (1)**; суммарное время линейно (рост в ~24 раза при n×30 — линейный тренд с
  поправкой на константы).
- **Свой `Deque.push_front`** — **O (1)**; суммарное время линейно (рост в ~48 раз при n×30 — линейный тренд). По
  константе медленнее `collections.deque` в ~4–9 раз: Python-объекты `_Node` против C-реализации. Асимптотика совпадает,
  что и требовалось.
- На малом n (1 000) `custom` сравним с `list` по константе (0.000135 vs 0.000122), но с ростом n `list` уходит в
  квадратичный рост, а `custom` остаётся линейным — преимущество дека проявляется именно на больших n.

## 4. Проверка корректности

`self_check()` покрывает:

- `factorial` — сверка с `math.factorial` для n=0..11;
- `fib_naive`/`fib_memo` — значения для n=10 и `CALLS["fib_memo"] < CALLS["fib_naive"]`;
- `hanoi` — формула 2ⁿ−1 для n ∈ {0,1,3,8};
- `DynamicArray` — инвариант `size ≤ capacity`, сверка с `list` на 100 элементах (несколько границ роста), `IndexError`
  за границей;
- `Stack` — LIFO-порядок, сверка с `list`;
- `Deque` — FIFO и работа с обоих концов, сверка с `collections.deque`, `IndexError` на пустом.

**Честная оговорка:** `self_check` для `Deque` не покрывает отдельно сценарий «`pop_back` на деке из одного узла»
(последний `pop_front` снимает единственный элемент, а `pop_back` на опустошении тестом не проверяется). Этот сценарий
прогнан вручную по всем четырём случаям (пусто / 1 / 2 / 3 узла) для каждой из четырёх операций — ошибок нет.
Рекомендация на будущее: добавить в `self_check` цикл, снимающий элементы по одному с обоих концов до опустошения.

## 5. Выводы

1. Наивная рекурсия Фибоначчи экспоненциальна (O (φⁿ)), мемоизация сводит её к O (n) — счётчик вызовов подтверждает
   разницу на порядки.
2. `factorial` — O (n) по числу операций (пометка `O = n²` в docstring — опечатка), `hanoi` — ровно 2ⁿ−1 перемещений.
3. `DynamicArray.append` — амортизированное O (1): замеры `t/n` дают плато, метод учёта (3 токена) обосновывает границу.
4. Дек на двусвязном списке даёт **строгое O (1)** на всех четырёх операциях концов — без амортизации, в отличие от
   `DynamicArray` (там O (1) амортизированное из-за `_grow`).
5. Замеры подтверждают: `list.insert(0,x)` квадратичен суммарно, `collections.deque` и свой `Deque` — линейны; свой дек
   медленнее по константе (Python vs C), но асимптотически эквивалентен.

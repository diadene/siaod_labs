## 1. Что сделано

| Компонент           | Реализация                                                                                                  |
|---------------------|-------------------------------------------------------------------------------------------------------------|
| `factorial(n)`      | рекурсивно, базовый случай `n=0 → 1`                                                                        |
| `fib_naive(n)`      | наивная рекурсия `F(n)=F(n−1)+F(n−2)`, счётчик `CALLS["fib_naive"]`                                         |
| `fib_memo(n, memo)` | рекурсия + мемоизация в словаре, счётчик `CALLS["fib_memo"]`                                                |
| `hanoi(n)`          | рекурсивно, возвращает число перемещений                                                                    |
| `DynamicArray`      | буфер фиксированной ёмкости, рост ×2 через `_grow()`                                                        |
| `Stack`             | LIFO поверх `DynamicArray` (`push`/`pop`/`peek`)                                                            |
| `Deque`             | двусвязный список `_Node(value, prev, next)` с `__slots__`; `push_front`/`push_back`/`pop_front`/`pop_back` |

## 2. Сложности и обоснования

| Операция                                        | Сложность                 |
| ----------------------------------------------- | ------------------------- |
| `factorial(n)`                                  | **O(n)**                  |
| `fib_naive(n)`                                  | **O(φⁿ)**, φ≈1.618        |
| `fib_memo(n)`                                   | **O(n)**                  |
| `hanoi(n)`                                      | **O(2ⁿ)**                 |
| `DynamicArray.append`                           | **амортизированное O(1)** |
| `Stack.push/pop/peek`                           | амортизированное **O(1)** |
| `Deque.push_front/push_back/pop_front/pop_back` | **строго O(1)**           |

**Инвариант пустого дека:** `_head is None ⇔ _tail is None`. В `pop_front`/`pop_back` при опустошении обнуляются **обе** ручки — иначе вторая остаётся на «мёртвом» узле.

**Порядок присваиваний** в `push_*`/`pop_*` важен: сначала сохраняем ссылку (в новом узле или в переменной), потом
переставляем ручку — иначе старая ссылка теряется до использования.

## 3. Замеры (вариант 4, seed=34)

### 3.1 `DynamicArray.append` — демонстрация амортизированного O (1)

|       n | всего t, c |   t/n, c |
|--------:|-----------:|---------:|
|   1 000 |   0.000102 | 1.02e-07 |
|   3 000 |   0.000330 | 1.10e-07 |
|  10 000 |   0.001208 | 1.21e-07 |
|  30 000 |   0.003466 | 1.16e-07 |
| 100 000 |   0.012948 | 1.30e-07 |

**Вывод:** `t/n` держится в узком диапазоне ~1.0–1.3e-07 с без роста при увеличении n в 100 раз —  амортизированное O (1).  При O (n) на операцию `t/n` росло бы линейно с n.

### 3.2 Вставка в начало: `list.insert(0,x)`, `collections.deque` , свой `Deque`

|      n |  list, c | deque, c | custom, c | list/deque | list/custom |
|-------:|---------:|---------:|----------:|-----------:|------------:|
|  1 000 | 0.000122 | 0.000031 |  0.000135 |       3.9× |        0.9× |
|  3 000 | 0.000902 | 0.000085 |  0.000373 |      10.6× |        2.4× |
| 10 000 | 0.009728 | 0.000262 |  0.002049 |      37.1× |        4.7× |
| 30 000 | 0.082059 | 0.000742 |  0.006520 |     110.6× |       12.6× |

**Вывод:**

- `list.insert(0,x)` — **O (n) на операцию** (сдвиг всех элементов); суммарное время растёт n². При росте n в 30 раз время выросло в ~670 раз.
- `collections.deque.appendleft` — **O (1)**; суммарное время линейно (рост в ~24 раза при n×30).
- **Свой `Deque.push_front`** — **O (1)**; суммарное время линейно (рост в ~48 раз при n×30)
  константе медленнее `collections.deque` в ~4–9 раз: Python-объекты `_Node` против C-реализации.
